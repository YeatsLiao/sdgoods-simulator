# sdgoods-simulator — 音频实现细则

改 `web/js/audio/**` 或排查电台/断续/连续收听时再读本文。

- 扬声器：接受 16-bit 或 32-bit PCM，采样率与声道数随 `I2sFormat` 报文（电台常见 48 kHz 立体声），在 `engine.js` 用 `codec.js` 的 `createResampler` 跨报文保持相位地流式重采样到 AudioContext（每声道一个实例，格式不变就复用）。低电平的网络音频由 `applyMakeupGain` 做响度自适应：目标 RMS 0.12、期望增益限在 1×–16×、RMS 达到 0.096（目标的 0.8 倍）即视为够响不再抬升、低于一个 16-bit LSB 视为数字静音并冻结当前增益；头余量按 `0.9/峰值保持` 封顶（峰值每块衰减 0.995，避免相邻 5 ms 块之间跳变），按块平滑（快攻 0.04、慢放 0.02）；只抬升不压制，固件音量仍然有效。`levels.makeup` 报的是本块实际施加的增益，不是平滑后的存储值。
- `worklet.js` 扬声器侧：3 秒环形缓冲（溢出丢最旧帧）、±1 安全钳位、自适应预缓冲、每 100 ms 电平上报。分段/语音档的预缓冲从 60 ms 起，每出现一次断流翻倍到 1 s 上限，连续 2 秒无断流再减半，跟得上的固件保持低延迟；剩余缓冲低于 30 ms 低水位时用 5 ms 淡出收尾，避免硬切断点的咔哒声；淡出期间缓冲回补要重新打开这一段。一次断流只计一次欠载。主线程用 `{type:"live", on}` 停放环形缓冲：缓存或连续回放占用输出期间只出静音，不计欠载、不动预缓冲。
- 连续回放（`engine.js`，新用户默认关闭，旧显式偏好保留）：到达率低于实时时，把设备音频缓存成一段（默认 4 秒，可选 2／4／8／16 秒，上限 30 秒），用 `AudioBufferSourceNode` 原速播完，播放期间同时缓存下一段；起播时刻取 `max(ctx.currentTime, 上一段 endsAt)`，接得上就无缝衔接，接不上就等下一段攒满。每段两端 5 ms 淡入淡出消掉边界咔哒，`onended` 里断开并释放 source。回放期间 `levels.outRms`／`outQueued` 报的是这一段自身的 RMS 与剩余样本数，不是空的环形缓冲。`flush()` 与 `close()` 必须停掉正在播的段并摘掉 `onended`。开关与时长持久化在 `audioReplay`（`shared/storage.js`）。
- 到达率由 `codec.js` 的 `trackArrival` 在主线程统计（每 1 秒窗口，上限 2×），随 `AudioEngine.levels` 暴露，「音频」面板与性能面板显示。本机模式的实时倍率来自 `server/native_worker.py` 解析的 `SIM/CLOCK` 模拟时间增量（协同仿真秒／墙钟秒）；WASM 模式该值由 CPU 周期数折算，两者口径不同，不要互相比较。电台类音频受 ESP-EMU 算力限制，到达率会低于 100%，表现为断续而不是无声，不要当成解码故障。
- 实测口径（电台、本机加速）：`esp-emu` 独占一核 100%，`realTime` 与到达率同为 0.18–0.35（随场景与主机负载变化），`--batch-size` 无改善——断续来自模拟速度上限，不是管道或解码。播放占空比等于到达率，实时路径做不出连续播放；连续回放把同样的字节整理成完整语音段加段间等待，实测 4 秒段约每 12.6 秒一段、占空比约 32%、段内无切断。要真正连续收听请用「连续收听（浏览器取流）」。不要再去查缓冲、CPU 或带宽。排查「没声音／杂音」先看欠载次数与报文数之比，再看格式与原始 PCM 电平。
- 连续收听（跟随设备电台，`web/js/audio/direct.js`，默认开启）：唯一能连续听的路径是让浏览器接设备正在播的那一路地址，声音不再来自 I2S。地址来源是固件开流日志 `radio_player: net: connected, streaming: <url>`（`sdgoods-radio` 里带上，旧固件没有这行就无法自动跟随，只有 302 跳转行 `http 302 -> <url>` 可用作补充），`parseStreamUrl()` **取拼接缓冲里的最后一条**——尾巴里留着上一台，取第一条会永远卡在旧地址。日志按块到达，`app.js` 留 400 字符尾巴再解析。`DirectStreamPlayer` 用一个 `<audio>` 取流，浏览器负责解封装与抖动缓冲；`isDirectPlayable()` 只按地址形态拒绝 `.m3u8`／`.mpd`／`.pls`。播放期间 `AudioEngine.setExternalAudio(true)`：设备 PCM 只统计到达率，不解码、不重采样、不入环；设备连续 4 秒没送 I2S（退出电台、暂停、关机）就自动交还输出并提示，手动地址那一路不受这个计时约束。切台时上一路的 `play()` 会被浏览器中断（AbortError），`this.#station.url` 已变就静默让位，不许报「取流失败」；停止后迟到的 `error` 事件同样忽略，否则面板会被涂成失败。读数用 `state.continuous`（已连续秒数）与 `state.gaps`（打断次数），直播流的 `buffered` 只是两三秒滚动窗口，显示出来会被读成卡住。音量与静音跟随底部控制栏，`audioDirect` 存跟随开关。这段声音绕开固件的解码与音量逻辑：验固件音频链路要关掉跟随或用连续回放／真机，录屏音轨仍是设备侧输出。
- 麦克风：16000 Hz、32-bit、1 通道、小端；16-bit 样本左移 16 位。
- 实时播放走 AudioWorklet，连续回放走 `AudioBufferSourceNode`；不要用 `ScriptProcessorNode` 作为主路径。
- 麦克风默认关闭，使用时才请求权限；回声消除/降噪/自动增益默认关闭，提供诊断电平。
- 音量、静音、PA 使能状态要与 UI 一致；音频缓冲欠载必须计数。
## 游戏低延迟（2026-11-20）

- 新会话默认实时互动。声音面板的「播放方式」提供「游戏低延迟」与「分段回放（允许延迟）」；已保存的 `audioReplay.auto=true` 继续保留，需要显式选择游戏档。高级回放开关与此选择器同步。
- 游戏档关闭自动缓存，切换时停止全部已启动/排队的 BufferSource，清空部分缓存，并通过 `{type:"latency", mode:"interactive"}` 清空 Worklet 旧队列。此前只跟踪最后一个回放源会遗留前面排队的旧声音，现用 Set 回收全部源。
- Worklet 游戏档预缓冲 20–80 ms，实时队列最多 120 ms，超限丢最旧帧。语音档保留 60–1000 ms 与原 3 秒容量。不要把游戏档恢复成逐次断流无限增大缓冲。
- `AudioContext` 显式请求 `latencyHint: "interactive"`。这是浏览器策略请求，不是端到端延迟保证，见 https://www.w3.org/TR/webaudio/#dom-audiocontextoptions-latencyhint 。
- 电平回报新增 `prerollMs` 与 `dropped`；AudioEngine 的 `outQueued` 仍是音频帧数，`queueMs` 才是毫秒。性能面板现在使用 `queueMs`，不可把帧数直接标成 ms。
- 120 ms 是浏览器实时队列的硬上限，20–80 ms 是起播门槛，两者不能相加解释为端到端延迟；固件计算、协同仿真传输、系统声卡和蓝牙输出另有延迟。模拟速度不足依然会断音，丢旧帧只能避免额外积压。
- 本地 `sdgoods-doom/build_pub/sdgoods-doom-full.bin`（8,098,027 字节）、本机模式已运行到游戏及菜单。采样一次队列 57.7 ms、预缓冲 80 ms、音频到达率约 48%，另一次到达率约 45%。这些是特定主机的一次观测，未测按钮到扬声器的端到端延迟，未做人耳录音对照。
- 回归新增真实 SpeakerProcessor 合成突发/欠载测试，验证队列裁剪和预缓冲上限；双段回放切回实时验证每个 source 都停止。原电台直连、重采样和响度算法保留。


## 2026-11-25 用户要求移除高级播放界面

工作台不再挂载音频诊断页、播放策略选择、连续回放或手动直连地址控件。`ui/audio-panel.js` 仅返回基础麦克风按钮与启用后电平；音量/静音仍使用 AudioEngine 与 DirectStreamPlayer 的统一控制。正常启动以 `applyReplayPrefs(null)` 使用实时播放，不再从旧 `audioReplay.auto` 激活隐藏的分段回放；旧偏好存储不删除，以便回退，内部引擎回放能力与测试保留。此条覆盖此前旧显式回放偏好继续驱动公开工作台的约定。

自动跟随固件电台保持原有逻辑，PCM、重采样、响度、Worklet 与网络算法未改。声音断续提示不再推荐已经移除的页面或选项。诊断数值可供内部性能统计，不在设置中堆叠；UI 只保留音量、静音、麦克风及启用后的输入电平。


### 工作台声音入口（2026-11-25）

声音是开发工具独立页签，只展示音量、静音和麦克风。音量/静音由 App.setSoundPreferences 统一保存并同步实时输出与浏览器取流路径，刷新/重启/切换固件后沿用；麦克风必须主动开启。高级播放与诊断不再作为可见 UI；本次不修改 PCM/Worklet 算法。
