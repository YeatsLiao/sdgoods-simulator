# 谷仓次元屏模拟器产品化升级方案

> 版本 v0.1 · 2026-11-17
> 范围：本地版（开发者）+ 官网嵌入版（消费者）
> 参考：FoloToy Passport Simulator、谷仓固件市场、ESP-EMU v1.1.0

## 1. 目标

把现在“能跑一个 Chiikawa 整机包”的验证工具，升级为谷仓次元屏的官方在线体验与调试入口：

1. 打开网页就能选官方市场的玩法，一键运行，不装环境。
2. 运行稳定不卡顿，有扬声器声音和麦克风，触摸/侧键/控制中心可用。
3. 开发者能看日志、查状态、截图录屏、复现问题，而不是只能看画面。
4. 官方市场卡片可以直接跳转“在模拟器中运行”，后续嵌到 sdgoods.ai。
5. 同一套代码支持本地调试和官网托管，不把固件上传到服务器。

### 2.2 关键限制

| 限制 | 影响 |
|---|---|
| 只支持从 0x0 开始的整机合并镜像 | 市场里的纯 app 包不能直接运行 |
| 示例按钮写死 0.1.0 | 新固件要手动选择 |
| 无音频、麦克风 | 音乐、语音、提示音类玩法体验缺失 |
| 无跨重启 Flash 持久化 | NVS、设置、进度每次重启丢失 |
| 无官方市场列表 | 用户必须自己找 BIN |
| 调试只有串口日志 | 寄存器、GPIO、截图、输入复现都不方便 |
| 浏览器模式约 5 帧/秒，本机约 18 帧/秒 | 重负载玩法体验差 |
| Windows 本机模式依赖 WSL | 首次使用门槛高 |
| 无官方嵌入/深链协议 | 官网对接需要额外改造 |

### 2.3 性能基线

2026-11-17，Windows Edge + Chiikawa GO 0.1.0，草地讨伐场景：

| 模式 | 实际绘制 | 结论 |
|---|---|---|
| 浏览器 WASM | 约 5 帧/秒 | 受 WASM 单线程模拟速度限制 |
| 本机加速 | 约 18 帧/秒 | 可作为 Windows 默认推荐模式 |

### 2.4 上游能力边界（已核对 ESP-EMU v1.1.0）

| 能力 | 结论 |
|---|---|
| ESP32-S3 CPU / PSRAM / Flash | 支持 |
| Wi-Fi（Soft AP + user-mode 网络） | 支持，现有启动参数未启用 |
| I2S 标准/TDM/PDM、扬声器与麦克风 | 协议支持，现有模拟器未接入 |
| Flash 状态导出/保存 | WASM `flash_state()`；原生 `--save-state` |
| 复位/擦除/读写区域 | 原生 `--control-tcp` 支持，可免重启切换固件 |
| GDB、ELF 符号化、Perfetto trace | 支持，现有模拟器未暴露 |
| Windows 原生二进制 | 不提供；Windows 需 WSL 或浏览器模式 |

## 4. 产品定位与原则

### 4.1 三种使用场景

| 场景 | 用户 | 默认模式 | 界面 |
|---|---|---|---|
| 官网体验 | 普通用户 | 浏览器 WASM | 简洁模式：设备 + 玩法库 + 运行 |
| 本地调试 | 开发者 | 本机加速 | 开发者模式：串口、性能、音频、网络、调试 |
| 市场运营 | 官方/作者 | 深链/嵌入 | 玩法卡片 + 运行结果 + 埋点（可选） |

### 4.2 原则

1. **本地优先**：固件不下发到服务器，浏览器模式完全在本地运行。
2. **官方包为准**：市场条目直接使用官方文件与哈希，不二次打包、不转存。
3. **性能分层**：有 WSL/Linux 用本机加速；没有则浏览器模式，明确提示能力差异。
4. **调试优先**：每个失败都能看到日志、固件信息、崩溃原因，而不是只有黑屏。
5. **消费者与开发者分界面**：默认简洁，开发者模式才显示高级面板。

## 7. 核心能力设计

### 7.1 官方玩法库（P0）

#### 数据流

1. 页面加载 `GET /api/firmwares?scope=market`、`/api/categories`、`/api/stats`。
2. 卡片显示截图、名称、版本、大小、分类、官方/置顶、安装数。
3. 点击“在模拟器运行”：
   - `full`：下载合并镜像 → 校验 SHA-256 → 启动。
   - `parts`：逐段下载 → 按 `address` 写入 32 MB 稀疏 Flash → 启动。
   - `app`：下载纯应用包 → 拼装单应用镜像 → 启动。
4. 下载与拼装结果进入缓存；再次运行直接命中。
5. 记录最近运行与上次版本。

#### 包形态处理

| `packageForm` | 内容 | 运行方式 | 风险 |
|---|---|---|---|
| `full` | 合并整机镜像 | 直接作为 `--firmware` | 低 |
| `parts` | 引导、分区表、应用、系统资源分段 | 按地址拼装稀疏镜像 | 中：地址重叠/越界校验 |
| `app`（标准） | 纯应用包，不带地址 | 官方 bootloader + 分区表 + app@0x10000 + 空 otadata | 中：需官方基础镜像 |
| `app`（超 3 MB 或自定义布局） | 例如 PixMon 9.17 MB | 暂标记“需官方适配”，不静默失败 | 高：需官方提供布局 |

单应用模式与平台文档一致：`launcher/factory` 区写入 app，擦除 otadata，开机直接从 factory 启动；appdata 保持空白或复用上次快照。

#### 缓存与校验

- 以 `fileSha256` 为键缓存文件；分区包缓存每段。
- 校验大小、SHA-256、镜像魔数、分区表签名。
- 解析 `esp_app_desc_t`：工程名、版本、IDF 版本、编译时间，显示在卡片和运行页。
- 缓存上限可配置；LRU 淘汰；支持离线运行已缓存条目。

#### 深链与官网嵌入

| 参数/接口 | 作用 |
|---|---|
| `?app=<marketId>` | 打开并加载指定玩法 |
| `?fw=<url>&sha256=<hash>` | 直接运行外部固件（需白名单） |
| `?embed=1` | 隐藏导航，适配 iframe |
| `?mode=native|wasm` | 指定运行方式 |
| `postMessage` | `sim.ready` / `sim.booted` / `sim.error` / `sim.fps` / `sim.screenshot` |
| 父页面调用 | `run(appId)` / `reset()` / `screenshot()` / `setMute()` |

官网嵌入时同源访问 `/api`，避免 CORS；本地开发由 `serve.py` 代理。

#### 官方侧需要配合

1. 市场 API 允许模拟器域名读取，或直接同源部署。
2. 为每个固件提供稳定的 `installPlan`（`full` / `parts` / `app + base`），尤其是 PixMon 这类超槽位或自定义布局的包。
3. 提供或授权内置基础镜像（bootloader + 分区表），并给出版本与哈希。
4. 市场卡片增加“在模拟器中运行”，链接到深链。
5. 明确固件、截图、基础镜像的再分发与展示许可。

### 7.2 性能（P0）

#### 渲染

- 用 WebGL2 直接把 RGB565 作为纹理上传，着色器转 RGBA，替换逐像素 JS 写入。
- 渲染放在 OffscreenCanvas/Worker，主线程只处理 UI。
- 只提交完整 LCD 窗口；按 `requestAnimationFrame` 合并，丢弃过期帧。
- 预留脏矩形接口，后续按窗口增量上传。

#### 本机传输

- 把“每次运行启动一个 WSL 进程”改为常驻本机守护进程：
  - 一次启动 WSL + ESP-EMU，后续通过 `--control-tcp` 执行 `write-region` + `reset` 切换固件。
  - 浏览器与本机守护进程走 WebSocket（二进制帧），替代 HTTP 流 + 每次输入一个 POST。
  - 画面、音频、日志、输入共用一个多路复用协议。
- 保留当前 zlib 压缩；按实测调整压缩级别和 flush 策略。
- 会话结束、页面关闭、浏览器崩溃都要回收 WSL 进程和临时目录。

#### 浏览器模式

- 保持 Worker 内运行；调优批大小与时间片，加入 MIPS/实时倍率指标。
- 评估上游 WASM 构建是否启用 SIMD/线程；不承诺超出上游能力的帧率。
- 明确提示：重负载游戏推荐本机加速；浏览器模式以“能玩、可体验”为目标。

#### 性能预算（目标值，按场景验收）

| 指标 | 目标 |
|---|---|
| 本机模式 Chiikawa 草地场景 | ≥ 25 帧/秒（当前约 18） |
| 浏览器模式简单玩法 | ≥ 12 帧/秒；重负载不承诺 |
| 输入到画面响应 | 本机 < 100 ms |
| 音频端到端延迟 | 本机 < 150 ms；浏览器 < 250 ms |
| 冷启动（已缓存） | < 3 s |
| 切换玩法（本机常驻） | < 3 s |
| 页面内存 | < 500 MB（含 32 MB Flash 快照缓存） |

### 7.3 音频（P0 播放，P1 麦克风）

已核对板级引脚与 ESP-EMU 协议：

| 方向 | 引脚 | 格式 |
|---|---|---|
| 扬声器 | DOUT 47 / BCLK 48 / WS 38 / MCLK 15 | 16 kHz、16-bit、立体声 |
| 麦克风 | DIN 17 / BCLK 16 / WS 2 | 16 kHz、32-bit、单声道 |
| 功放使能 | GPIO3，高有效 | 用于静音/电平指示 |

实现：

1. 在协同仿真注册中增加 I2S claim（扬声器 + 麦克风）。
2. 解析 `I2sFormat` / `I2sOut`，把 PCM 送 AudioWorklet 环形缓冲；按 AudioContext 采样率重采样。
3. 麦克风用 `getUserMedia`，关闭回声消除/降噪/自动增益，降采样到 16 kHz，打包为 32-bit 单声道 `I2sIn`。
4. 音量、静音、输出设备选择；观察 GPIO3，功放关闭时静音。
5. 音频诊断：电平表、缓冲深度、欠载次数、当前采样率、测试音、WAV 导出。
6. 原生模式经 WebSocket 传音频；WASM 模式先做可行性验证，若受限则先只在本机模式提供音频。

### 7.4 调试（P0 基础，P1 深度）

| 能力 | 内容 |
|---|---|
| 串口 | 彩色分级、时间戳、搜索、暂停、清空、下载；输入发送；快捷命令 `?` / `s` / `R` |
| 固件信息 | 工程名、版本、IDF、编译时间、分区表、Flash 占用 |
| 性能 | MIPS、模拟时间、实时倍率、FPS、绘制耗时、丢帧 |
| GPIO | 输入/输出状态，触摸/侧键/功放使能可视化 |
| 寄存器/内存 | WASM 面板；原生通过 GDB 或 trace |
| GDB | 一键开启 `--gdb 1234`，显示连接命令；冻结/继续/复位 |
| ELF | 选择 ELF 获得符号化回溯；崩溃时自动暂停并生成报告 |
| Trace | 导出 Perfetto JSON，分析任务与耗时 |
| 输入 | 触摸坐标叠加、宏录制/回放、脚本化验收 |
| 截图/录屏 | PNG 截图；WebM 录屏（含声音）；分享卡片 |
| Flash | 快照导出/导入、清除 NVS、恢复出厂、查看写入量 |
| 崩溃报告 | 日志 + 固件信息 + 回溯，一键复制，便于提 issue |

开发者模式与简洁模式分开；官网默认隐藏高级面板，URL `?dev=1` 开启。

### 7.5 Flash 持久化（P0）

- **本机模式**：每次会话使用独立 Flash 文件；退出时 `--save-state`；重启复用同一文件；支持“清除数据”删除覆盖层。
- **浏览器模式**：用 `flash_state()` 导出完整 Flash，按 4 KB 块与基础镜像做稀疏差分，压缩后存 IndexedDB；下次启动用 `load_firmware` 载入合成后的镜像。
- 键：`hardware + appId + version`；版本变化默认提示“是否保留数据”。
- 支持导出 `.bin`、导入 `.bin`、恢复出厂；限制单条快照大小，超限提示。

### 7.6 网络（P1）

- 本机模式：ESP-EMU `--net user`（零配置 NAT）+ 虚拟 AP（SSID/密码可配）。
- 浏览器模式：默认仅内部网络；需要联网时引导下载 `esp-emu-relay`，连接本机 relay。
- 网络面板：AP 信息、DHCP 租约、TCP/UDP/DNS 连接、收发字节、连接活动；不显示敏感载荷。
- 配网类玩法提供“模拟配网”入口：预设 SSID/密码，重置 Wi-Fi 配置。

### 7.7 交互与产品化（P0/P1）

- 首次引导：运行时下载、模式选择（本机/浏览器）、音频权限、网络说明。
- 加载状态：下载进度、校验、拼装、启动分阶段；失败给出可操作按钮。
- 设备操作：侧键、电源闩锁、音量、亮度、全屏、键盘快捷键（R 重启、空格侧键、S 截图）。
- 移动端：触摸优先、底部面板、横竖屏；不展示需要鼠标的高级功能。
- 中英文、深浅色、可访问性；错误文案避免术语。
- 分享：当前玩法 + 版本 + 截图 + 深链；不包含固件内容。
- 兼容性声明：屏幕/触摸/音频/Wi-Fi/按键支持，BLE/NFC/电池不模拟；发布固件前仍需真机复测。

### 7.8 安全与合规（P0）

- 本地服务只绑定 `127.0.0.1`；保留现有 Origin 校验；会话 ID 使用 UUID；限制固件大小。
- 市场文件只从官方域名下载；逐段校验 SHA-256；拒绝路径穿越和超范围地址。
- 固件视为不可信输入；模拟器沙箱运行；不挂载宿主目录；不执行固件中的任意命令。
- 麦克风/网络默认关闭，使用时明确授权；日志默认本地。
- 增加 LICENSE 与第三方声明；ESP-EMU、LVGL、字体、素材分别标注。
- 官方市场内容不转存、不二次分发；基础镜像需官方授权。

## 9. 验收标准

| 场景 | 验收 |
|---|---|
| 市场 `app`（番茄时钟） | 一键拼装并启动，画面/触摸正常 |
| 市场 `parts`（电子吧唧） | 分段拼装启动，系统资源区生效 |
| 市场 `full`（DOOM / 小智） | 直接启动，重启后仍可运行 |
| 音频 | 扬声器有声音，音量/静音有效，无明显爆音；麦克风回环可用 |
| 性能 | 本机 Chiikawa ≥ 25 帧/秒；输入响应 < 100 ms |
| 持久化 | 设置/进度跨重启保留；“清除数据”恢复初始 |
| 调试 | 串口双向、截图、录屏、崩溃回溯可用 |
| 官网 | 深链和 iframe 嵌入可启动；无 CORS 错误；移动端可用 |
| 安全 | 非本机 Origin 无法调用原生接口；市场文件校验失败时拒绝运行 |

## 11. 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| WASM 模式 I2S 音频未验证 | 浏览器无声 | 先做本机音频；WASM 做 Spike，失败则官网提示“本机模式有声” |
| Windows 本机依赖 WSL | 首次使用门槛 | 一键安装引导；浏览器兜底；评估 Windows 原生/云端 |
| 纯 app 包布局不统一 | 部分玩法无法运行 | 包校验 + 明确标记；推动官方返回 `installPlan` |
| 浏览器模式性能上限 | 重负载玩法卡顿 | 本机模式优先；性能预算按场景分级 |
| 32 MB Flash 快照大 | 存储与加载慢 | 稀疏差分 + 压缩；按需保留 |
| 上游 ESP-EMU 变更 | 兼容性回归 | 锁定版本与哈希；升级前跑回归 |
| 麦克风隐私/回声 | 用户顾虑、啸叫 | 默认关闭、明确授权、回声消除开关 |
| 市场内容许可 | 无法展示/分发 | 只引用官方文件；基础镜像书面授权 |
